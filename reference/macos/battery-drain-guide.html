macOS Power Management · pmset

Battery Drain Mode — keep your Mac awake until 0%

Three terminal settings that let your Mac run flat-out on battery — lid closed or open — until the battery is critically low and macOS powers itself off. Safe, reversible, and fully explained.

🧑‍💻 Works on any MacBook ⚡ Apple Silicon + Intel 🔒 Reversible in seconds

⚡ How it works

Normally, a MacBook does three things that stop a battery-only run: it sleeps when you close the lid, it idle-sleeps after a few minutes, and it can hibernate to disk. All three are just software rules the system daemon powerd follows — and all three can be switched off with a tool called pmset (Power Management SETtings).

LayerWhat it controlsCan we change it?
pmset settingsidle sleep, lid-close sleep, display sleep, hibernationYES — with sudo
powerd daemonapplies those settings, negotiates App Nap / energy useIndirectly (via pmset)
Battery / SMC firmwarefinal safety cut-off at ~1–2% batteryNO — hardware

The important part is that last row: even with every sleep disabled, the Mac still shuts itself off when the battery hits ~1–2%. That cut-off lives in the battery controller firmware and cannot be disabled by software. This is the safety net that makes the whole trick safe — the run always ends cleanly by itself, at nearly 0%.

The golden rule: you can only delay sleep, never defeat the low-battery cut-off. So the worst case is a dead battery and a clean power-off — exactly what "drain to 0%" means.

Why would anyone do this?

  • Battery calibration — a full drain-and-recharge cycle every few months keeps the battery gauge honest.
  • Benchmarking runtime — find out how long your Mac actually lasts under load.
  • Headless tasks — close the lid and let it crunch overnight without sleeping.

⚙️ The four settings

Everything is controlled by four pmset values. Here's what each one means, its normal value, and its drain-mode value.

SettingCommandNormalDrain modePlain English
disablesleep pmset -a disablesleep 1 0 1 The lid-close switch. Normally, closing the lid = sleep. With 1, the lid is treated like a screen-off only — the Mac keeps computing.
sleep pmset -a sleep 0 10 min 0 = never Idle system sleep. 0 means "never idle-sleep", even with the lid open.
hibernatemode pmset -a hibernatemode 0 3 0 3 = sleep-to-RAM (with disk backup in some versions). 0 = never hibernate — nothing gets frozen to disk mid-drain.
displaysleep pmset -a displaysleep 5 5 min 5 (leave it) Display timeout. The screen is the biggest power draw, so let it sleep on its own — it doesn't stop the drain.
The -a flag means all power sources (battery + charger). -b would be battery-only, -c charger-only. -a is the right choice for a drain test.

Checking the current state

pmset -g | grep -iE 'sleepdisabled|sleep |displaysleep|hibernatemode'

Look at SleepDisabled: 1 = drain mode on, 0 = normal.

🚀 Run it, step by step

1

Optional: decide the starting level

Unplug the charger at any level — the trick works from any %, it just takes longer the fuller the battery. (~1 hour per 25% is a rough guide on Apple Silicon.)

2

Enable drain mode

Run this in Terminal (or double-click ~/Desktop/battery-drain-mode.command and pick option 1). You'll be asked for your admin password:

# Disable lid-close sleep, idle sleep, and hibernation
sudo pmset -a disablesleep 1 sleep 0 hibernatemode 0
Note: if something else is already preventing sleep (e.g. a caffeinate process), pmset -g may show "sleep prevented by powerd". That's harmless — the drain still happens.
3

Start the battery logger (optional but recommended)

Logs battery % every 60 seconds to ~/battery-drain.log — your proof the Mac kept running with the lid shut. The command file does this for you, or manually:

# Append timestamp + battery % every 60s (runs until the Mac powers off)
nohup bash -c 'while true; do echo "$(date '\''+%F %T'\'') $(pmset -g batt | grep -oE '\''[0-9]+%'\'' | head -1)"; sleep 60; done' >> ~/battery-drain.log &
4

Close the lid and walk away

Lid closed, on a table — not in a bag (see Warnings). Two low-battery alerts will pop up around 10% and 3%; ignore them or dismiss them.

5

Wait for the power-off

When the battery hits roughly 1–2%, the Mac powers itself off — no action needed. That's the end of the run.

6

After: charge, then restore

Plug the charger back in. Once it's back on, restore normal sleep behaviour:

# Restore: lid-close sleep on, 10-min idle sleep, 5-min display, default hibernation
sudo pmset -a disablesleep 0 sleep 10 displaysleep 5 hibernatemode 3 standby 1
pkill -f battery-drain-log.sh   # stop the logger if you used it

(The double-clickable ~/Desktop/battery-drain-mode.command also has a "Restore" option that does all of this for you.)

Verify it worked: tail -f ~/battery-drain.log while it drains — timestamps should keep advancing every minute with the lid shut. If numbers climb with time and end at ~1%, the whole run worked.

📊 Reading the battery log

While drain mode is on, the logger appends one line per minute to ~/battery-drain.log. Each line is timestamp + battery % — nothing else:

2026-09-29 12:05:57 39%
2026-09-29 12:06:57 39%
2026-09-29 12:08:02 38%
2026-09-29 12:09:57 37%
… (one line every 60 seconds, % tick-ing down) …
2026-09-29 13:31:03 1%
⏻ log ends here — that's the power-off
  • Timestamps keep marching → the Mac stayed awake (lid-close + idle sleep defeat working).
  • % keeps dropping → it's genuinely draining.
  • The log stops → the run ended. The last line is usually 1–2%.

Handy commands

tail -f ~/battery-drain.log   # watch the drain live
head -3 ~/battery-drain.log && echo "…" && tail -3 ~/battery-drain.log   # start vs end of the run
The logger dies with the Mac — that's expected, not an error. If the log keeps growing after you expected it to be dead, you're not at 0% yet. Wait.

⚠️ Warnings & FAQ

🔴 Don't put it in a bag while it's running

A closed-lid Mac that's awake generates heat with nowhere to go. On a desk or table it's fine — inside a backpack or sleeve it can overheat badly. Keep it flat and ventilated for the whole drain.

🔴 Draining to 0% every day kills the battery

Lithium-ion cells dislike full discharges. The battery industry guideline is a full drain-and-recharge once every few months for gauge calibration — not daily. Treat this as a calibration ritual, not a habit.

🔴 What does "0%" actually mean?

Software never lets a lithium battery truly hit 0. The firmware reserves the last ~1–2% as a hard floor, then commands a shutdown. So "until it closes" really means "until the Mac powers off around 1–2%".

🟡 Does this work on Apple Silicon (M-series)?

Yes — disablesleep works on both Apple Silicon and Intel MacBooks. The pmset option has existed for years and is honoured by current macOS (26.x). If Apple ever removes it, third-party tools like Amphetamine do the same job via a GUI.

🟡 Will it also ignore the display sleep setting?

No — displaysleep is untouched. The screen still sleeps on its own timer, which is good: the display is the single biggest power consumer, so letting it shut off drains slower and the lid-close case has no screen anyway.

🟡 What if the Mac powers off but won't turn back on?

That's normal right after a 0%-drain — it needs a few minutes of charging first. Plug it in, wait ~5 minutes, then power on. If it still won't boot after 15 min of charging, hold the power button for 10 seconds (Apple Silicon) and try again.

🟢 Do I need a password every time?

Yes — changing pmset system-wide requires admin rights, so macOS asks for your password each time you flip the settings. That's the same security boundary that keeps random apps from making your Mac never sleep.
