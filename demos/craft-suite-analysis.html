The claim I was asked to check "Did someone crack Adobe and give it away for free?" — No. These are independent, clean-room reimplementations written in Rust, published under MIT / Apache-2.0. What people actually did was point AI coding agents at the problem and re-build Photoshop's behaviour from the outside, at a speed that makes the result look impossible. That is a very different thing from a patched Adobe binary — and the difference matters, because "AI-cracked Adobe, free download" is one of the most reliable malware delivery stories on social media right now.

01Why it looks exactly like a crack

The tell is menu parity. PhotoCraft ships Photoshop's menus, shortcuts and even an "Adobe Camera Raw Filter" entry. If you only looked at the UI you would swear it was a repack. So I opened the installed binary and looked for Adobe's fingerprints.

A PSD reader has to speak those namespace strings — that is the format. There is no Adobe code in there to patch. What exists is a from-scratch implementation that reads and writes the same files.

02The AI part, though, is true

This is where the rumour comes from, and it is not a misunderstanding — it is an under-statement. The repositories ship an AGENTS.md (18.7 KB, literally "a guide for AI agents and contributors") plus an in-tree .claude/rules/ directory. The commit log behaves like an agent works: roughly 100 commits in under 24 hours across about ten contributors, in thirteen separate repositories, each one chasing 1:1 menu and shortcut parity with a commercial app.

the honest framing

People used AI agents to reimplement Photoshop-like behaviour from the outside, in Rust, and then gave it away. Nobody cracked anything. The software is genuinely free; the AI models are a separate, paid matter (see §06).

04The gap nobody mentions: the installer is half a product

Every one of these apps exposes its entire command registry to a headless CLI, a JSON control channel and a stdio MCP server — which makes them unusually agent-friendly. But the official launcher installs only the GUIs. There is no <app>-cli on your PATH afterwards, and nothing in the UI points at one. The CLI is a separate release asset per app: 

https://github.com/storytold/<app>/releases/download/v<ver>/<app>-cli-<ver>-macos-universal.zip

Thirteen apps × ~130 MB of CLI assets is not a thing anyone wants to assemble by hand, so I wrote the installer I wanted: resumable downloads (curl -C -), quarantine stripping, symlinks into ~/.local/bin, safe to re-run. It is in the download pack below, with a verifier that prints the table I used for §03.

Why #2 is the one that matters

A PDF "redaction" made by drawing a black rectangle leaves the text underneath, in the file, forever. This is the mistake that leaked real case files. I built a two-line PDF with a name under a black box and PdfCraft pulled the string back out and exited non-zero — so a script can refuse to publish a document that only looks redacted.

08Limitations, stated plainly

read before trusting a 0.x app with real work

It is alpha. PhotoCraft, PdfCraft and FigCraft still label themselves "early alpha"; the other ten say "in development". Keep originals, export to new filenames, never let one of these be the only copy of anything.

PdfCraft's OCR is Latin-only and worse than macOS Vision. It needs PDFCRAFT_MODELS=/Applications/PdfCraft.app/Contents/Resources/models to work at all, and --language zh is rejected outright. Chinese scans still go through Vision.

Command names are not Photoshop's. image.resizeImage does not exist — query <app>-cli commands instead of guessing. Argument styles differ too (--out x.png on PdfCraft, positional output on DeckCraft).

The website's own download button is broken on a Mac: getartcraft.com/apps serves a Linux .flatpak. Use the launcher release page. And getartcraft.com/app is a 404 — the web studio lives at app.getartcraft.com.

10What I would use it for, today

  • PdfCraft instead of pdftoppm + headless Chromium for page rasterising — 12 ms, no browser, plus an audit that catches fake redactions.
  • GridCraft wherever a formula must actually evaluate before I hand a workbook over; check is a real oracle, which openpyxl cannot do at all.
  • CADCraft → VectorCraft as the bridge from Fusion 360 DXF to laser-ready SVG with the text outlined for LightBurn.
  • WordCraft / DeckCraft for converting my own school and workshop documents without opening an office suite.
  • Not yet for video, audio or layout work — those five CLIs answer, but I have not proved a single timeline or mix.

Method. Installed the official suite, then installed each app's separately-released CLI, then ran every claim in §05 on this machine's own files (a DT poster, a Chinese guide, a school deck, a CAD bracket). Counts and sizes were produced by script, not by hand, and the pack's MANIFEST.json carries the same numbers so they can be re-derived.

Honesty notes. Five of the thirteen apps are marked "CLI responds" and nothing more — that is the whole of what I tested, and padding it would defeat the point of the page. The "AI cracked Adobe" framing is reported because it is what people are saying, not because it is true. Nothing here is cracked software and no third-party repack is linked: the only downloads are the projects' own GitHub releases.
