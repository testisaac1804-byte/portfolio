Why the shell ships as .txt: anything served with an HTML content-type gets rewritten in flight — this site's own skin injector appends a newline and a <script> block to every page, and Cloudflare appends its analytics beacon. A file you download as .html would therefore never hash to the manifest. Sent as text/plain, the bytes arrive exactly as captured, so the hash is checkable. Rename a copy to .html locally if you want to render the empty shell.

The live shell will drift as they redeploy — the value of a hash is that it pins the build this analysis was written against (Last-Modified 2026-09-14 11:43:40 GMT), not that the origin never changes.

What is not here, and why

The operator's backend is not here — no account, no API, no way in. What the teardown does publish is the front-end: ../tripo3d-uk-mirror/ runs the same 49 chunks (each still matching bundles.sha256) with a small guard that answers /api/announcement from the captured body and fabricates the rest locally, so the workspace and the eight /admin screens render without a real session — any password gets in, every number is a constant, and a submitted job ends in a sample model — the Khronos duck, labelled DEMO — after seven seconds of fake progress, never something generated from the picture you uploaded. The shell it boots from is the 3,396-byte document in this folder, with seven documented deltas (relative asset URLs, router base, guard + cache-buster, icon link, noindex) — see ../tripo3d-uk-mirror/MIRROR.md.

Do not enter a password you use anywhere else. The copy's login is a local stub — anything typed is accepted because nothing is checked and nothing is sent, so there is no reason to type a real one. This bundle never logs in, proxies or replays against the origin. If you want to look at the live site yourself, treat any account you create there as public: the operator can read your prompts, uploads and balance.
