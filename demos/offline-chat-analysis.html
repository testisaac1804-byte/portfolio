Offline Chat: a multi-user chat that needs zero internet

One Python file is the server, the client, and the protocol. It serves a chat room over whatever local network already exists — school WiFi, a phone hotspot, or a pair of Macs sharing a cable — and it never opens an outbound connection. Everything below is measured from the shipped offline_chat_v2.py, not from a plan.

What it actually does

1

No tunnel, no relay, no third party

The original launcher.py in this folder pipes traffic through an SSH tunnel so the room is reachable across the internet. That is exactly what was removed. v2 binds 0.0.0.0 and answers on the LAN interface only — nothing in the request path leaves the local network.

2

SSE instead of WebSockets

Server-to-client push is text/event-stream; client-to-server is a plain POST to /send. No websockets package, no uvloop, no FastAPI — just http.server.ThreadingHTTPServer. Any browser that can hold an EventSource open is a supported client.

3

The client is the page

The entire UI — 27,971 bytes of HTML, CSS and JS — is a Python string constant. There is no client/ folder to serve and no build step. Visiting / on a phone gets the same bytes a Mac gets.

4

Encryption without a CA

--tls generates a self-signed certificate at first run and caches it in the temp directory. If openssl exists it shells out; if it does not (stock Windows), a pure-Python RSA-2048 keygen plus hand-built X.509 DER takes over. Browsers show the familiar self-signed warning once.

5

Panic close

beforeunload and pagehide wipe document.body and clear stored state, so closing the tab leaves a blank white page rather than a readable transcript.

Anatomy: the certificate generator

Why it exists

Encryption is the difference between "a chat" and "a chat the network admin can read". But Windows ships without openssl, and a dependency on cryptography would break the zero-install promise. So the fallback builds the certificate by hand.

What it actually does

  • Miller–Rabin primes → RSA-2048 keypair in pure Python
  • DER writers for INTEGER, OID, SEQUENCE, BIT/OCTET STRING, UTCTime
  • sha256WithRSAEncryption (1.2.840.113549.1.1.11) over the TBSCertificate
  • PKCS#1 v1.5 padding, then PEM at 64 columns
Verified on both paths. macOS/OpenSSL 3.6.3 issues the cert instantly; forcing the fallback (empty PATH, system Python 3.9.6) still produced a 1,062-byte certificate that ssl.SSLContext.load_cert_chain() accepts, and the HTTPS server answered /health with tls:true.

What broke, and what it cost

SymptomCauseFix
Page rendered as unstyled text, no JS ran The template began life as an f-string, so every CSS/JS brace was written {{. Converting it to a plain string kept 204 doubled braces in the shipped HTML. Collapse {{/}} once at render time, before marker substitution.
SyntaxError: Unexpected string in the upload renderer \' inside a Python triple-quoted string is consumed by Python, so a nested window.open('…') reached the browser with no escapes. Dropped the nested quotes entirely: window.open(this.src).

Honest limitations. This is a LAN chat, not a radio. It cannot invent a network: every device must be able to reach the host's IP. On a school network that isolates clients (common on enterprise WiFi), two laptops on the same SSID still cannot see each other — the fix there is a phone hotspot or a direct cable, not code. TLS is a self-signed certificate, so the browser warning is expected and there is no protection against an active MITM who can already intercept your LAN. The password is checked server-side but the room state lives in process memory: kill the server and the transcript is gone. There are no OS firewall rules — earlier notes calling this "firewall-proof" were wrong; it is encrypted, not firewalled.

What is still not built

  • A transport of its own. Wi-Fi Direct / AWDL / Bluetooth pairing were considered and dropped: browsers cannot open those radios, and the host cannot create an ad-hoc network on macOS builds where "Create Network" is absent.
  • Persistence. No SQLite, no log file — by design, but it means no scrollback after a restart.
  • Cross-network rooms. Deliberately out of scope: the original tunnelled app already covers that case and stays in the folder.
