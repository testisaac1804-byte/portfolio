Security teardown · archived 19 Oct 2026
● Do not install

Universe Browser / 寰宇瀏覽器
ub66.com — "哪里都能去！" (go anywhere)

A browser marketed as the fastest, most private, safest way to browse — independently reported to behave like malware, and tied to the illegal-gambling cybercrime economy of Southeast Asia. Below: what researchers found, and what I verified directly against the live site, the Windows launcher and the Android package.

Bottom line

Do not install this, and treat ub66.com as unsafe. In October 2025 the network-security firm Infoblox, working with the UN Office on Drugs and Crime (UNODC), published research finding the Windows build covertly installs background programs, behaves like a keylogger, disables browser security features, routes traffic through China, and is distributed through a network of illegal gambling sites. My own inspection of the current build (below) confirms the operator identity, the China-hosted proxy infrastructure and a cluster of dangerous engineering choices — including a publicly distributed APK that is debuggable.

2 · What independent researchers found

Infoblox and UNODC reverse-engineered the Windows build. Their findings were covered by WIRED, Android Authority and Gadgets 360. Their conclusion: the features are "consistent with remote access trojans (RATs) and other malware."

Who is behind it

Infoblox traced the browser's web infrastructure to BBIN (also Baoying Group), an iGaming software supplier founded in Taiwan in 1999 and now based largely in the Philippines — grouped by researchers as threat actor "Vault Viper", connected to money laundering, illegal online gambling, human trafficking and forced-labour scam compounds. Researchers say the browser was advertised only on the domains Vault Viper controls, typically linked at the bottom of casino sites next to the BBIN logo — and that in criminal hands it would be "the perfect tool to identify wealthy players and obtain access to their machine."

3.2 · The download chain

The download button does not link to a file. It goes to a gate page that runs a fake CAPTCHA and then looks up the payload path from a JSON manifest:

www.ub66.com/download.html→ files/files.json→ cdn.n4dhx7bt.com
/files/2lDT9zYt…/→ UniverseBrowser.apk
UB-Launcher.exe

What files/files.json currently returns:

{"windows": "files/2lDT9zYtHf2hdZvAarEhmA/UB-Launcher.exe",
 "android": "files/2lDT9zYtHf2hdZvAarEhmA/UniverseBrowser.apk",
 "ios":     "https://apps.apple.com/cn/app/…id1541131030"}

Two anti-automation tricks in the download gate

  • The CAPTCHA is fake. download.html generates a 4-digit code in JavaScript (getRandomNumber()), draws it to a canvas, and compares your input against the same variable in the same page. No server is asked. It stops nothing except crawlers and sandbox scanners that won't solve it.
  • The download is deliberately delayed by a random 500–1500 ms (getRandomTime()) after a correct code, and retry limits are surfaced as server errors. This is sandbox-evasion pacing, not user experience.

3.3 · The payload host mints a new timestamp on every request

cdn.n4dhx7bt.com is an eight-character random domain registered 2021-09-29 at GoDaddy, delegated to throwaway-looking name servers (snm1z3c.88ylccne.com), fronted by CloudFront. Requesting the same APK three times in six seconds:

RequestLast-Modified returnedActual time
1stMon, 19-Oct-2026 15:11:38 GMT15:11:5x
2ndMon, 19-Oct-2026 15:11:41 GMT15:11:5x
3rdMon, 19-Oct-2026 15:11:58 GMT15:11:5x

The file does not change (identical Content-Length every time) — the header is generated from the clock at request time. The effect: every download looks like a freshly built, never-before-seen file. Cache validation, "have I seen this binary" reputation lookups and timestamp correlation against a known sample all stop working. This is a deliberate anti-forensics measure, and it is not something a legitimate software CDN does.

The file is named a launcher and is packaged with UPX, which compresses the executable so its real code and strings are not visible until it decompresses itself in memory. UPX is a legitimate packer, but on a consumer download with no code signature it is the standard way to make static analysis and signature-based antivirus fail. This matches the researchers' observation that the browser "covertly installs several programs" — a launcher is exactly the component that fetches and installs the rest.

3.7 · Inside the "acceleration technology": an SSH tunnel written in Go

The claimed "寰宇独家线路加速技术" (exclusive line-acceleration technology) is lib/arm64-v8a/libgojni.so — a 14 MB Go library whose internal package paths (normally stripped in release builds) are intact: 

/gomobile/src/ub66.com/HttpProxy/dududu/pkg/tunnel/ssh.go
/gomobile/src/ub66.com/HttpProxy/dududu/pkg/tunnel/tunnel.go
/gomobile/src/ub66.com/HttpProxy/dududu/pkg/failover/txt_lookup.go
/gomobile/src/ub66.com/HttpProxy/dududu/pkg/secretutil/rc4.go
/gomobile/src/ub66.com/HttpProxy/dududu/pkg/secretutil/teapotparser.go
/gomobile/src/ub66.com/HttpProxy/dududu/pkg/route/route.go
/gomobile/src/ub66.com/HttpProxy/dududu/pkg/forwarder/forwarder.go

Read together, that is the whole architecture, and none of it is "acceleration":

  • tunnel/ssh.go — the proxy is carried over SSH tunnels (it links golang.org/x/crypto/ssh). Your HTTP traffic is wrapped in an SSH session to their server, so it leaves your network looking like an SSH connection, not a web request.
  • secretutil/rc4.go + teapotparser.go — a custom framing protocol internally called "teapot" with RC4 obfuscation. RC4 is cryptographically broken and deprecated everywhere else; here its job is to hide the traffic from inspection, not to protect it.
  • failover/txt_lookup.go — the client finds its proxy servers through DNS TXT records. That is a takedown-resistance design: block or seize a host, change one TXT record, every installed client migrates. It also means the server list is invisible in the page source, the store listing, and to anyone who doesn't query TXT.
  • route/route.go — maintains a local database of the domains you visit (formatAndHashDomain, getRootDomain, an SQLite store). The client keeps a record of your browsing destinations on disk.

Live DNS TXT records on ub66.com — the failover channel is real

dig ub66.com TXT currently returns two opaque 33-character tokens:

"hhpnzkm1dcgb4jgds9w5kk41c8k8qf63"
"vggo8v3u1fs7rv3or2fhc7rmej"

These are not SPF, DKIM or domain-verification records — they are not in the formats those use. They are the kind of payload the txt_lookup failover path is built to consume.

3.8 · Where the tunnel actually goes: Alibaba Cloud, mainland China

The library contains hardcoded server addresses and a bootstrap resolver. Geolocating them:

This is the concrete form of the researchers' "routes traffic through servers in China": at least two hardcoded proxy endpoints sit on Alibaba Cloud in Shenzhen, mainland China, with a Hong Kong node and a Chinese DNS resolver baked in. Combined with the SSH + RC4 + TXT design, the picture is a private, obfuscated, China-rooted tunnel that the operator can re-point at will — and every byte you browse inside this browser passes through it in the clear at the exit.

An honest correction: it is not a device-wide VPN

Headlines saying it "routes all internet traffic through China" are easy to misread. I checked the manifest for a VpnService, accessibility service or device-admin receiver — none are declared. The proxy is org.chromium.base.local_proxy.ProtectorService, a Chromium component that redirects this browser's own traffic into the Go tunnel. So: pages you open in Universe Browser go through their servers; the rest of your phone's traffic does not. That is a meaningful limit on the damage — and it is still more than enough to expose everything you do in the app they built to be the thing you browse with.

4 · Threat model: who is actually harmed

Three distinct groups, with different exposure:

  • Gambling users (the intended market). The browser is pushed from casino sites to players who need to reach them. The operator then sits between the player and the world with a keylogger-capable client, contact and account access, and the ability to install more. The research conclusion is blunt: in criminal hands it identifies wealthy players and gets access to their machine.
  • Anyone who installs it to "unblock" something. You trade a block you can see for a middleman you cannot. Logins you type, pages you load, and the destinations you visit are all visible to the exit node — an exit node in mainland China, selected by DNS records the operator controls.
  • Bystanders. Contact and account permissions mean the harm does not stop at the installer.

5 · The archived page

A byte-faithful archive of the live landing page, captured 19 October 2026, running in a phone frame. It is the real page — same HTML, CSS, images and JavaScript — with three deliberate changes, because a live malicious-adjacent page should not be republished with its wires attached:

  1. All outbound network is blocked (guard.js): cross-origin requests, WebSockets and beacons fail. Verified: zero external requests on load.
  2. The download flow is disabled. The QR code and download button explain that this is an archive instead of producing a payload path. No APK or EXE is hosted here.
  3. The two Google Analytics beacons were removed so the archive does not report to the operator's analytics property from this site.

Try the buttons — the archive refuses, and the bar at the bottom of the frame marks it as a stored copy. The download gate page (download.html) is archived too, including its fake canvas CAPTCHA, but its payload lookup is blocked.

6 · If you already installed it

  1. Android: Settings → Apps → Universe Browser → Uninstall. Then run a Play Protect scan and change passwords for anything you signed into inside that browser, starting with email and banking. Revoke any account access you granted it.
  2. Windows: uninstall "Universe Browser"/"UB Launcher" from Apps & Features, then run a full scan with Microsoft Defender or Malwarebytes. Because the launcher is UPX-packed and installs further components, a clean scan is not proof — if it ran on a machine that holds accounts you care about, treat the machine as potentially compromised.
  3. iOS: delete the app; it has far less reach than the other builds but still sits between you and every site you visited.
  4. Then: if you used it to reach anything sensitive, change those credentials from a different, clean device.

7 · What to use instead

  • Privacy without a middleman: Firefox with Strict Tracking Protection, Brave, or Tor Browser.
  • If you genuinely need to reach a blocked site: a reputable paid VPN with a published no-logs audit — Mullvad, ProtonVPN, IVPN. Not a "VPN browser" from a casino-adjacent vendor, and not a free APK.
  • Rule of thumb: if a browser is distributed by sideloaded APK from a gambling site, no amount of "military-grade privacy" copy on the landing page changes what it is.

Limits of this analysis — stated plainly

  • I did not run the Windows build or the APK, so I have not reproduced keylogging or runtime behaviour myself. Those findings are Infoblox's and UNODC's, cited above; my work corroborates the identity, infrastructure and design, not the runtime telemetry.
  • The link to illegal gambling sites comes from the researchers' infrastructure mapping. The ub66.com landing page itself contains no casino content, no gambling links and no BBIN branding — the tie is in the operator identity (package bbin.*, certificate O=bbin), not on the page.
  • The DNS TXT tokens are consistent with the txt_lookup failover design and are not standard SPF/DKIM/verification formats, but I have not decrypted them, so I present that as strong inference rather than proof.
  • The dynamic Last-Modified header is a fact I measured. Why it is done is my inference — a legitimate CDN has no reason to do it.

Why the binaries are not republished here

This exhibit archives a public marketing page. It deliberately does not host, mirror or re-share UB-Launcher.exe or UniverseBrowser.apk. The hashes and file sizes are published so anyone can identify a copy they encounter; the files themselves stay where they are. Analysing a sample is not the same as distributing it.
