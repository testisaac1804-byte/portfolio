A single offline HTML file that turns seven official syllabuses — Pearson 4MA1, 4SD0, 4EC1 and Cambridge 0500, 0509, 0445, 0457 — into dated blocks from 26 Oct 2026 to 30 Apr 2028. The bar was not "cover the topics". It was every named part of every topic, each one with the syllabus reference it came from, and a way to prove none had been quietly dropped.

The constraint that shaped everything

Topic headings are useless for revision. "States of matter" is not a study session — gas pressure, diffusion and changes of state are. So the plan is built from the lowest named unit in each syllabus, and every block carries the reference it came from, so a weak answer can be traced back to a spec point instead of a vague topic.

Three checks, and they are separate

1 · Structure audit

Papers, durations, marks, weights, option rules — read off the official PDF, not a revision site. This is the check that catches "Edexcel Economics has a Paper 2 that was never scheduled".

2 · Coverage

Every sub-topic in the syllabus must appear inside a dated block. The build asserts unscheduled == 0; the app then re-derives it live from the rendered data, so the claim is visible rather than promised.

3 · Density

Coverage is worthless if it is one block per topic. Each unit gets a learn block plus at least one spaced re-touch: 1,422 blocks for 185 units ≈ 7.7 touches per unit.

The scheduler — queues, not a hand-written table

official PDF → pdftotext → numbered-point parser → unit inventory (185) │ ref, zh title, en title ↓ per-subject FIFO queue (spec order, pointer reset at every phase boundary) ↓ fixed weekly grid Mon 2 · Tue 2 · Wed 2 · Thu 2 · Fri 2 · Sat 4 · Sun 4 = 18 slots ↓ learn slot → next unit in the queue drill slot → the unit from two weeks ago (spaced), or this week's unit in weeks 1–2 review slot → error log + next week's titles ↓ JSON → single HTML → localStorage checkboxes → live coverage tab

Hand-writing 1,422 blocks would have been both slow and unverifiable. Generating them from 185 units and a slot grid means the coverage claim is arithmetic: the build fails loudly if any unit never appears, and the app recomputes "0 / 185 complete, 185 scheduled" from the same data the user clicks.

Anatomy of a block

{"k":"w1-0","day":"一","sub":"Chem","ref":"4SD0 Chem 1.1–1.4", "title":"物質三態","en":"States of matter", "task":"① 讀 4SD0 Chem 1.1–1.4 官方 spec ＋課本 ... ② 做 6 題分類 past paper ③ 錯嘅即刻抄入錯題本"}

Seven fields, no free text: the key drives the checkbox, the reference drives the audit, the task text is generated from the subject so it always says what to do (read → produce → practise → log errors) rather than what to think about. The Chinese title is the label Isaac actually reads; the English title is the syllabus name, kept so an adult or a tutor can map it back without translation.

Honest limitations. (1) The plan starts at Chem 1.1, Phys 1.1, Bio 1.1 — it does not know the school's current position; if the class is already past a unit, the matching block has to be skipped forward by hand. (2) D&T is planned as Paper 3 Materials; if the school enters Graphic Products the option units (2.1–2.5) change. (3) 18 blocks a week ≈ 12 h is a full schedule; holidays are labelled but not lightened, and no catch-up week is pre-built — a missed week is a manual decision, not an automatic reshuffle. (4) Progress lives in localStorage per browser; it does not sync between devices and clearing site data clears it. (5) The 25 full papers in phase 3 assume the 2020–2027 past papers are available for each subject; if one session is missing, that week becomes a second weakness week instead.

How it is used

Five tabs

  • 本週 — jumps to today's week, 18 tickable blocks
  • 全部週 — 79 cards with phase, holiday tag and per-week progress
  • 課題覆蓋 — 185 units, green when every related block is ticked
  • 卷別校對 — the audit tables above, inside the app
  • 錯題本 — autosaved log

Deliberate omissions

  • No account, no sync, no server — it opens from the Desktop with no network
  • No drag-and-drop rescheduling; edits happen by regenerating from the same script
  • No streak gamification — a missed week should look missed, not be rewarded

What is next

The generator lives at ~/.hermes/scripts/igcse80/ — units.py (the 185 units), build.py (scheduler + renderer) and a headless test that asserts coverage and clicks every tab. When the school's position or the D&T option is confirmed, the plan is regenerated rather than patched, so the coverage guarantee survives the edit.

Method. Official syllabus PDFs → pdftotext -layout → numbered-point and lettered-heading parsers → unit inventory → scheduled with a fixed slot grid → rendered to one self-contained HTML file → verified headlessly (coverage assertion, DOM counts, checkbox persistence, tab rendering) and visually (screenshots of every tab).
Honesty notes. No number on this page is inherited from a previous draft: weeks, blocks, units, sizes and the hash are re-derived from the current artifact. The syllabus issues are quoted with their issue numbers because Pearson keeps one standing issue per specification, while Cambridge publishes a version per three-year window — the table names which one covers 2028 for each subject. The plan is a schedule, not a prediction: it says what to study on a given Monday, not that the result is guaranteed.
