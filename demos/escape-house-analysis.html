Escape House — a Desmos escape room, rebuilt as one offline file

The original is a Desmos activity: rooms, codes, items and flags all living inside a graphing calculator's expression list. This is a rebuild of it as a single 85,196-byte HTML file that opens with no network, no assets and no install — 21 rooms across three levels, six lock mechanics, the original's exact codes, and a three-tier hint system that reads your own save file to know which step you are stuck on.

Two requirements, and the second one is a design problem rather than a feature: a hint button that is useful while somebody is inside a puzzle, not only between puzzles.

The Desmos activity stores its whole game in the expression list. Reading the exported state gives the real structure — not what the screenshots look like, but what the author wired up:

The flags are brace-named, which is why naive grep misses them: the switch is u_{lightsOn}, the trapped door is u_{iceKey}, the dart is u_{sedDart}. Strip the braces and the whole dependency graph falls out of the click actions. Every code in this rebuild came out of that graph — 131 on the kitchen drawer, 962 on the bedroom keypad, 4 5 19 13 15 19 on the bookcase panel (A1Z26 for DESMOS), and 7:30 for the clock.

4 · the two mechanics the first pass missed

1

The clock is a container, not a clue

The first rebuild used the clock as a wall code only. In the original the clock takes two inputs — the hands from the library shelf and the time from a UV mark in the basement — and then opens, with the bike chain inside. That chain is the only thing that makes the living-room bike do anything, and the bike is a dead end on purpose: the author put a payoff there with no lock behind it.

2

The computer is three puzzles in a row

Screwdriver to open the panel → four nodes to align → power button → lights-out grid → the disk drive ejects. The first pass collapsed all of that into a single click. Also corrected: the screwdriver in the original opens the computer panel, not the keypad — the keypad's gate is its own flag (u_{keypadOpen}), and the two were being conflated because both are in the bedroom.

5 · the hint system

The request was a button for people “doing the thing and they don't know how to do”. A single “here's the answer” button fails that: it either spoils the puzzle or says nothing useful. So the hint is a ladder — three rungs per puzzle beat, and it knows which beats you have already passed.

Rung 1 · direction

No answer, no object, no room unless you are lost. “Something in the kitchen is cold enough to lock a key.” Enough to restart a stalled player.

Rung 2 · the move

“Open the fridge and take the ice cube, then select it and click the hot tap.” The action, in order, still without handing over a code.

Rung 3 · the answer

The code itself, plus the room it belongs to. Only on the third ask for the same beat — a player who re-asks twice has stopped enjoying being stuck.

Where it lives

Header button and the H key; plus a 💡 Stuck? button inside every lock panel, so the hint is reachable from behind the modal backdrop — the exact moment it is needed.

How a hint is chosen

// one beat = one line of puzzle progress
HINTS[level] = [ { id, room, done(G), need(G), t:[rung1, rung2, rung3] } … ]

resolveStep():
  1. if a lock panel is open        → the beat that panel belongs to   (context wins)
  2. else first beat where          !done(G)  &&  need(G)              (never a step you cannot reach)
  3. else                           → "everything here is done, head for the exit"

escalation:  new beat → rung 1 · same beat again → rung 2 · again → rung 3 (capped)
idle:        55 s with no click → the button itself starts pulsing

Three properties that matter more than the wording:

  • State-derived, not scripted. done(G) reads the same save object the game writes, so a hint cannot be out of date after a reload or a level restart.
  • Context beats order. Open the drawer with the ice still in the fridge and you get the drawer hint (beat 9), not the ice hint (beat 1) that a strict sequence would return.
  • Steps you cannot reach are skipped. need(G) keeps the ladder from telling a player to go and use an item they have not found yet.

32 beats across the three levels — 18 in the house, 7 in the lab, 7 in the vault. The counter (9 / 18) and the dots are the player's own progress bar; they are not decoration, they are the reason the ladder feels like help rather than a walkthrough.

6 · where this is not the original

Read this before comparing the two side by side.
  • The art is redrawn, not lifted. Every prop in this build is procedural SVG I wrote (fridge, counter, clock, bookcase, bike, cactus, server rack). The original's 175 images are the activity author's artwork and were not shipped. Layout, hotspots and codes match; brushwork does not.
  • Four UV clues exist, their room assignment is inferred. The codes are exact — 131, 962, 4 5 19 13 15 19, 7:30 — but the clue graphics are polygons drawn in the graph, not images, so the state dump cannot say which wall carries which number. The placement here is chosen so the chain stays solvable in one direction.
  • The lights-out grid is 5×5, not 8×8. The original uses 64 cells. 64 in a modal on a phone is a different game; the mechanic is identical, the difficulty is not.
  • No hard mode. The original carries an unused hardMode switch; it is not wired up here yet.
  • Levels 2 and 3 are mine. The Desmos activity has the house. The Lab and The Vault are new content built on the same engine and the same hint ladder.

9 · what's next

  • Wire the original's hardMode: one rung instead of three, for players who want the ladder to give only a direction.
  • An 8×8 lights-out behind an “authentic” toggle, keeping 5×5 as the default.
  • Re-draw the nine house rooms at the original's density — right now each room carries 3–6 props where the activity has 15–25.

Method. The Desmos activity state was exported and parsed rather than screenshotted: 794 expressions walked for clickableInfo actions, brace-named flags normalised, and every code read out of a comparison against a literal array in the graph. The rebuild was then re-derived from that graph and verified by playing it — a scripted headless-Chrome run that clicks real hotspots through the full level-1 chain and asserts each hint beat flips to done.
